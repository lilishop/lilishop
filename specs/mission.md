# Lilishop 项目使命

> 本文档依据 `lilishop`、`lilishop-ui`、`lilishop-uniapp`、`docker` 四个仓库的 `README.md` 中的利益相关方诉求，并经访谈确认后落盘。  
> 访谈日期：2026-08-17。

## 1. 一句话使命

打造可商用的 B2B2C 多商户电商平台：平台运营、多店铺入驻、全端购物（PC / H5 / 小程序 / APP）形成完整闭环。

## 2. 使命分层

| 层级 | 内容 | 来源 |
| --- | --- | --- |
| 首要使命 | 可商用的 B2B2C 多商户电商平台 | 访谈确认 |
| 能力支撑 | Docker / All-In-One 私有化与一键体验；二次开发友好（四仓边界清晰）；多语言商城；微服务 / Spring Cloud 作为可选演进（不是当前形态） | `README.md`「适用于 / 核心特性」+ 访谈确认 |
| 约束条件 | AGPL-3.0：个人学习、研究、非商业用途可使用；商业销售与商用必须获得官方授权 | `README.md`「开源与授权」+ 访谈确认 |

开源学习不是本项目的首要使命，也不单独写成目标用户。它是 AGPL-3.0 开源形态的自然结果，予以尊重即可。

直播、分销、秒杀等营销能力，以及结算 / 台账 / 钱包等财务能力，属于产品功能与路线图，不抬升为使命层目标。

## 3. 利益相关方诉求（摘自四仓 README）

四个仓库把产品定义为：基于 Spring Boot / Spring Cloud / Vue / Uniapp 的 Java 开源商城，支持 B2B2C 多商户、小程序、微服务、直播电商、分销返佣、秒杀、Docker 私有化部署。

核心能力诉求：

- 全端覆盖：一套代码库支持 PC、H5、小程序、APP
- 商家入驻：多商家入驻，构建平台化电商生态
- 分布式 / API 服务化：后端可独立部署
- 前后端分离：职责清晰，便于团队协作
- 容器化：Docker 镜像、docker-compose、All-In-One 一键体验
- 业务完整：客户、订单、商品、促销、店铺、运营、统计等模块齐全
- 多语言商城

适用场景：企业级商城、私有化部署、Java 商城二次开发、开源源码学习、多商户电商平台。

`docker` 仓额外强调：All-In-One 只用于本地体验、演示或验证，不代表生产高可用架构。`lilishop-ui` 仓额外强调：`common-api` 已下线，前后端按 `/buyer` `/store` `/manager` 路径对接。

## 4. 目标用户群体

访谈确认的必须服务对象如下。渠道运营方（微信小店 / 抖店）不写入本次 specs 的用户定义，也不进入路线图。开源学习者不单独成目标。运维 / 私有化部署诉求并入二次开发团队。

### 4.1 平台运营 / 管理方

- 入驻审核、平台规则、运营配置
- 全站统计、经营报表
- 使用端：平台管理端（`manager-api` + `lilishop-ui` 运营端）

### 4.2 入驻店铺 / 商家

- 店铺装修、商品发布、订单履约、营销活动、对账
- 使用端：店铺管理端（`manager-api` 商家安全域 + `lilishop-ui` 商家端）

### 4.3 C 端消费者

- PC / H5 / 小程序 / APP 浏览、下单、支付、售后
- 使用端：商城 PC（`lilishop-ui`）与移动端（`lilishop-uniapp`），后端为 `buyer-api`

### 4.4 二次开发 / 实施团队

- 基于全端开源源码做业务扩展与私有化部署
- 运维与一键体验诉求并入本群体，不单列「运维用户」
- 依赖：本仓库后端、`lilishop-ui`、`lilishop-uniapp`、`docker` 四仓协同，以及官方文档

## 5. 成功标准

对平台运营方、入驻商家、C 端消费者、二次开发团队同时成立时，使命才算达成：

1. 平台可以审核入驻、配置规则、观察经营数据。
2. 商家可以独立经营店铺（商品、订单、促销），而无需改源码。
3. 消费者可以在 PC / H5 / 小程序 / APP 完成购物闭环。
4. 二次开发团队可以按四仓边界做私有化部署与模块扩展：能分清 lite 体验与生产拆分，不被过期架构图、过期徽章或已下线的 `common-api` 路径误导。
5. 多语言作为已宣传能力，后续改动不得把某一端锁死在单语言。
6. 微服务 / Spring Cloud 若要演进，必须单独立项；当前成功不依赖「已经是 Spring Cloud」。

## 6. 非目标

- 不以「纯开源教学 Demo」作为产品方向。
- 不以单店 B2C 替代 B2B2C 多商户模型。
- 不以绕过 AGPL-3.0 / 商业授权的方式支持商业销售。
- 不以渠道运营方（微信小店 / 抖店）作为用户；本次 specs 与路线图不写渠道对接。
- 不以开源学习者、客服 IM、独立运维岗作为必须服务的用户群体。
- 不以 All-In-One 单容器冒充生产高可用架构。
- 不以 README 宣传语假装本仓已经引入 Spring Cloud。
